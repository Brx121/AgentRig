# 工程执行规则

下列规则用于后端任务，由 `backend` 配置启用。存储与异步决策与语言无关，阈值按项目配置。纯前端任务不加载这些规则。项目可以在 `.harness/ARCHITECTURE.md` 中记录实际架构。

| 领域 | AI 常用做法 | 工程执行规则 |
| --- | --- | --- |
| 数据存储 | 直接把数据保存成 JSON 文件，或把大对象塞进数据库字段。 | 根据数据量、查询方式、一致性要求和生命周期选择数据库、对象存储或文件；超过 1 MB 的对象使用对象存储，数据库只存 metadata。 |
| 异步任务 | 把可后台完成的批量处理、导出或耗时不稳定的任务放在请求里同步等待，超时后反复调大 timeout。 | 先判断当前响应是否必须拿到最终结果。可以先确认受理的耗时或耗时不稳定任务，交给队列和 worker，尽快返回任务 ID，并提供状态或结果查询。反复发生请求超时时，先定位耗时来源并重新判断是否应在请求中等待；适合后台执行的任务应改为异步，不能靠反复延长请求超时维持同步。预计超过默认 3 秒，或耗时难以预估时，必须评估异步方案。保留同步要说明理由和端到端时延预算。后台任务要明确并发上限、重试、取消和失败可观测性。 |

## 决策模板

处理新任务时，AI Agent 必须先回答：

1. 假设与不确定点：哪些信息缺失，采用什么假设？
2. 数据模型与存储选择：为什么选择数据库、对象存储或文件？
3. 异步/并发策略：当前响应必须拿到最终结果吗？耗时是否超过评估阈值（默认 3 秒）或难以预估？如果后台执行，如何返回任务 ID、查询状态或结果，以及控制并发、重试和取消？如果保留同步，为什么，端到端时延预算是多少？
